# AIPM demo: Resolve Faster records

This repository holds the **AIPM records** for *Resolve Faster*, a fictional customer-support program at the fictional online outdoor-gear retailer Lumen Ridge Outfitters. It shows how outcome agreements, evidence briefs, decision briefs, experiment cards, dependency records, benefits reviews, and applied lessons can live as GitHub issues on a Project board, next to the tools where delivery data actually sits.

AIPM (Adaptive Intelligence for Program Management) is an outcome-centered approach to project, program, and portfolio management. *Human judgment establishes purpose and accepts responsibility; AI helps people examine evidence, challenge assumptions, and adapt.*

## Where things live in the demo

| Tool | Holds |
|---|---|
| monday.com | Portfolio candidates and the executive status board |
| Jira | Delivery backlog, RF-3 test tracker, risks, dependencies |
| **GitHub (this repo)** | AIPM records as issues, created from issue forms; Project board "Resolve Faster – AIPM Records" |
| Documents | Status notes, vendor email, business case, experiment results (would live in SharePoint) |

## How records work

- Open a record with **New issue** and pick a form: Outcome agreement, Decision brief, Experiment card, Dependency record, or Applied lesson.
- Labels give the record type (`aipm:outcome`, `aipm:evidence`, `aipm:decision`, `aipm:experiment`, `aipm:dependency`, `aipm:lesson`, `aipm:benefits`) and its state (`status:proposed`, `status:approved`).
- **A record is a proposal until a named human approves it.** Only the named owner moves a record to `status:approved`.
- Milestones are the decision points: steering committee (2026-10-23), security approval needed (2026-11-06), Q1 2027 portfolio decision (2026-11-13), holiday freeze (2026-11-20), and the outcome review (2027-03-31).
- Append results; do not edit original hypotheses, thresholds, or baselines after the fact.
